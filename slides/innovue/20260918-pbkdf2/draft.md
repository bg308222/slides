# PBKDF2：一個密碼，可以變成什麼

> 定位：**小型科普**。主線 13 頁（不含封面外的隱藏頁）。
> 目標不是教密碼學，是讓聽眾拿到一把能自己用的尺，並看懂自己那段 code 為什麼被標成 obsolete。

---

## 這場分享要讓聽眾經驗什麼

### 目標觀眾與他們已知的起點

- 寫過登入功能、知道密碼「要 hash 再存」的工程師。
- **不預設聽過 8/07 bitwarden 那場**。凡是要用到密碼／驗證的地方，都用一般化的說法自足地講完
  （「把一個 master password 變成一個送出去驗證的值」——不需要 zero-knowledge、vault、symmetric key 任何一個名詞）。
- 對 `Rfc2898DeriveBytes` 可能有印象、但沒讀過它在做什麼。

### 最後應能自行說出的結論

不是「PBKDF2 是什麼」，而是能指著畫面回答三句話：

1. **iterations 就是把攻擊者的單價乘上去**——而且是乘一個常數，不是質變。
2. **它就只是一個「input 一樣就穩定產出、而且算起來很貴」的 bytes 產生器**。
   長度你自己定，切完拿去幹嘛也是你自己決定 —— RFC 管到 bytes 產出來就結束了。
3. **舊 API 被廢棄，是因為它的 input 少一個**：`PBKDF2 (P, S, c, dkLen)` 有四個輸入，
   那個建構子只收三個，長度被推遲到 `GetBytes`。少了一個 input，它就不是規格書定義的那個函式。

### 刻意不講的邊界

- **不講 XOR、不講 block index、不講 `INT(i)`**。最簡模型只到「一輪餵給下一輪、密碼每輪都要用到」。精確版全部進隱藏頁。
- **不展開 Argon2 / bcrypt / scrypt 的機制**。memory-hard 只在收尾一句帶過，不開章節。
- **不展開 HMAC 的內部**。只用到「密碼是 HMAC 的 key」這一個性質。
- **不展開 rainbow table 這個名詞**。用「一次動作 vs 一千次動作」代替（見 P5）。
- **不展開 IV 不該從密碼導出的完整理由**。P13 一句話點到為止，細節進隱藏頁。
- **不做 live demo**，全部用動畫演示（同前幾場）。

## 全場判讀尺

### 核心問題

> **「攻擊者猜一次，要付多少錢？」**

### 為何它能跨每一段檢查狀態

這場的核心取捨就是成本，而成本是唯一一個從頭貫穿到尾、每一步都會變的量。

| 段落 | 用尺量出來的結果 |
|---|---|
| P4 明文 | 不用猜，直接拿 |
| P5 hash | 算一次 → **可以拿去比對全庫**。破一個人的成本 = 破整個 db 的成本 |
| P6 hash + salt | 這一列算完對下一列沒用 → **每一列都得從頭再算**（但**單價還沒變**） |
| P7 | 那個單價 = **45 皮秒**（一秒 220 億次）。太便宜 |
| P9 | 單價 45 皮秒 → 68 微秒，× 150 萬倍。但爛密碼那格還是只有一分鐘 |
| P11 | 同樣的單價，買到的是一串沒有身份的 bytes —— 身份是你給的 |
| P13 | 少了「長度」這個 input，它連 PBKDF2 都不算 |

到 P10 之後，尺會多出一個問句和它並行：**「這串 bytes，是誰決定它多長、誰決定它拿去幹嘛？」**
兩個問句一起把最後三頁收掉。

## 推導主線

### 第一段（P3）：兩次遇見

- **已知／畫面起點**：無。這是動機交代，**刻意不拋任何問題、不設懸念**。
- **內容**：兩件各自獨立的小事——
  1. 之前讀 bitwarden 的 whitepaper 時，把 password hashing 當先備知識跳過了，但 PBKDF2 在那份文件裡反覆出現。
  2. 最近把 dotnet8 升到 dotnet10，有段 code 冒出 obsolete 警告，查下去發現它也是 PBKDF2。
- **這一頁唯一的功能**：把那段 code **第一次放上畫面**（不解釋，只讓大家看一眼），最後一頁會回到它。
- **留下的下一題**：無。直接進第二段。

### 第二段（P4–P7）：密碼要怎麼存

- **已知／畫面起點**：**先把題目講出來**——「使用者註冊時給你一個密碼，你得把它存下來；之後他來登入，你要判斷得出『這次打的對不對』。」
  在此之前聽眾只知道有個東西叫 PBKDF2，還不知道我們要解什麼；沒有題目，就沒有「直覺」可言。
  題目講完，畫面才長出那張 db 表格（欄位 `帳號 / 密碼`）。
- **痛點遞進**：明文 → 直接可用；hash → 反推不回來了，但同密碼同結果，**他算一次就能比對全庫**，破一個等於破全部；hash + salt → **這一列算完對下一列完全沒用，每一列都得從頭再算**。
- **新的可見狀態**：攻擊者「算一次」的效力，從「涵蓋全庫」縮成「只涵蓋一列」。
- **留下的下一題**：**那他算一次，到底要多久？**（P7 給出單價：太便宜）

> 這一段是三步遞進、不是三個並列的改良。
> 每一步只解掉上一步明確指出的那一件事，最後一步刻意解不掉，留給 PBKDF2。

### 第三段（P8–P9）：把單價乘上去

- **已知／畫面起點**：P7 那張「太便宜」的表。
- **小步**：參數表上多一個 `iterations`。同一件事重複做，成本就是乘法。
- **新的可見狀態**：同一張表長出第二欄。
- **留下的下一題**：表上還有一格沒解釋——**參數表其實有第四個欄位。**

### 第四段（P10–P11）：它到底在產什麼

- **已知／畫面起點**：P8 建立的參數清單。
- **痛點**：清單上有個 `輸出長度`。存密碼根本用不到這個參數——hash 的長度是演算法決定的，你不能跟 SHA-256 要 32 bytes 以外的東西。**那 PBKDF2 為什麼要讓你指定？**
- **小步**：攤開 **RFC 8018 §5.2 的簽章原文**。前三個是安全性參數，`dkLen` 不是 ——
  它是 *"intended length in octets of the derived key"*，一個介面參數。而輸出叫 **derived key**。
- **新的可見狀態**：一個函式、四個 input、一串 bytes。
  同一組 input 永遠同一串（所以驗證得了），而且算一次很貴（所以值錢）。**就這兩件事。**
  這串 bytes 要拿去幹嘛 —— 送出去比對、留著開資料、抽 64 個切一半 —— **RFC 一個字都沒寫**。
- **留下的下一題**：**那我們那段 code，抽了多少、拿去幹嘛？**

> **⚠️ 這一段最容易做壞的地方**：不要把它畫成「兩條固定的分岔」。
> 那會讓聽眾以為 PBKDF2 有幾種法定用法，然後回頭去背它們。
> 要傳達的是「隨你」—— 用途是**你**決定的，這樣 P13 才問得出「那 48 是誰決定的」。

### 第五段（P12–P13）：回到那段 code

- **已知／畫面起點**：P3 出現過的那段 code，原封不動搬回來。
- **P12 小步**：用 P11 那把尺量它兩下 —— **抽了多少**（32 + 16 = 48 bytes）、**拿去幹嘛**（自己切成 key + IV 餵給 AES）。
  它就是 P11 那張圖的其中一種用法而已。
- **P13 痛點（全場收束，只有一個論證）**：RFC 的簽章是 `PBKDF2 (P, S, c, dkLen)`，**四個 input**。
  那個建構子只收三個。`dkLen` 被推遲到 `GetBytes`，還可以一次一次地拿。
  **所以它從一開始就不是「一次 PBKDF2」，是一條 stream，而規格書裡沒有 stream 這種東西。**
- **收尾**：回收 P12 那個 48 —— 沒有人決定過它，那是兩次 `GetBytes` 自己掉出來的。
  新的靜態方法沒有變聰明，它只是**不讓你不講長度**。

> **⚠️ P13 不要開 SHA-1 / 1000 輪那條線。**
> 那是簽章裡 `Options: PRF` 那一行的事，跟「Input 少一個」是不同的故事，
> 兩個並列會把論證稀釋成「這個 API 有兩個毛病」，而不是「它根本不是那個函式」。
> SYSLIB0041 與預設值細節放附錄 D，被問到再翻。

## 逐頁／逐揭露設計

> 標 **★** 者為不可壓縮的關鍵頁。

### P1　封面

- PBKDF2 大標。
- 小標把五個字展開，**首字母用特別顏色**標出來讓人看出這是縮寫：
  **P**assword-**B**ased **K**ey **D**erivation **F**unction **2**
- 講者資訊。
- **講者不解釋這五個字**。展開只是讓它掛在那裡；`Key Derivation` 這兩個字要到 P10 才會被聽眾真正讀懂。

### P2　Outline

四段（跟前面的推導主線對齊，但標題寫成聽眾語言，不寫「介紹 X」）：

1. 兩次遇見 —— 不是什麼大哉問，就是兩件小事剛好指到同一個東西
2. **密碼要怎麼存** —— 從明文一路走到加了 salt 的 hash，然後問：**存進 db 的那個值被偷走之後，攻擊者猜一次要多少錢？**
3. 把單價乘上去 —— PBKDF2 只做這一件事
4. 回到那段 code —— 它到底在做什麼，以及為什麼被標成 obsolete

> 第二段的標題必須把**對象**講出來（存進 db 的那個值），不能只寫「猜一次要多少錢」——
> 沒有對象，聽眾不知道在猜什麼。

### P3　兩次遇見　★

- **畫面上有什麼**：左右兩格，各放一件事。
  - 左：bitwarden whitepaper 的截圖／一行引用，`PBKDF2` 這個字在裡面反覆出現（可高亮數處）。
  - 右：那段 code，加上 IDE 的刪除線／黃色波浪底線與 `SYSLIB0060` 的 tooltip。

  ```csharp
  var db = new Rfc2898DeriveBytes(password, salt, iterations);
  var key = db.GetBytes(alg.KeySize / 8);
  var iv  = db.GetBytes(alg.BlockSize / 8);
  ```

- **此頁的 click**：左邊出現 → 右邊出現。就兩下。
- **聽眾此刻應看出的事**：沒有要看出什麼。這頁不是謎題。
- **講者要說的話**：「一次是我自己跳過的功課，一次是升版被警告攔下來。都指到同一個東西，所以回去看了一下。」
- **不要做的事**：不要問「你們知道它為什麼 obsolete 嗎」。不要暗示右邊那段 code 有問題——只說編譯器不讓它過。
- **下一個痛點**：無。P4 從零開始。

> **編排理由**：code 提早 9 頁出現，代價是聽眾當下看不懂，收益是 P12 可以直接說「就是這段」而不需要重新建立語境。
> 這頁的 code 是**佈景，不是教材**——所以不逐行講，也不要停留太久。

### P4　密碼要怎麼存　★

- **標題底下第一行（click 之前就在）**：「使用者註冊時給你一個密碼，你得把它存下來 —— 之後他來登入，你要判斷得出『這次打的對不對』。」
  **這一行是整個第二段的地基**，不能省。省掉的話 P4 會變成憑空跳進來的一張圖。
- **step 0 的那句話**：「最直覺的答案：那就存起來啊。他登入的時候比對一下就好。」
- **畫面上有什麼**：中間一張 db 表格。

  | 帳號 | 密碼 |
  |---|---|
  | andy | hunter2 |
  | bob | hunter2 |
  | carol | p@ssw0rd |

  右側一個 attacker 的框（此刻是空的）。
- **此 click 唯一發生的事**：一條線從 db 拉到 attacker，整張表被複製過去。
- **聽眾此刻應看出的事**：他不用猜，他直接讀。
- **下一個痛點**：那就別存明文。

### P5　存 hash　★

- **畫面上有什麼**：同一張表，`密碼` 欄換成 `hash` 欄。**位置不動、行數不動**，只換欄位內容與欄名。

  | 帳號 | hash |
  |---|---|
  | andy | `9f2a…` |
  | bob | `9f2a…` |
  | carol | `c41d…` |

- **click 1**：表格換成 hash。attacker 那格的複製品同步變成 hash。
- **click 2**：把 `andy` 和 `bob` 那兩格 `9f2a…` 同時高亮——**一模一樣**。
- **click 3**：attacker 那邊長出一個動作：他猜 `hunter2`，算出 `9f2a…`，一條線同時指向表上的兩列。
- **聽眾此刻應看出的事**：他**只算了一次 hash**，然後拿這個值去跟每一列比——比對是免費的。
  所以 andy 中的那一刻，**bob 也跟著一起中，他一次都沒多算**。
- **講者要說的話**：「反推不回來是真的。但他從來就不需要反推——他只要猜一個、算一次，然後拿去比。
  換句話說，**破一個人的成本，跟破整個 db 的成本一樣。**」
- **⚠️ 不要說成**「一次動作解決整張表」。真正發生的是：**算的次數跟 db 有幾列無關**，
  而且所有 hash 相同的帳號會一起淪陷。這兩件事不一樣，後者才是 salt 要打掉的東西。
- **下一個痛點**：怎麼讓「算一次」不再能算給全部人？

> **不要用「rainbow table」這個詞。** 畫面上的「一條線指向兩列」比名詞有用得多。

### P6　加 salt

- **畫面上有什麼**：同一張表，中間插入 `salt` 欄。三個 salt 值明顯不同。

  | 帳號 | salt | hash |
  |---|---|---|
  | andy | `x7Kq…` | `9f2a…` |
  | bob | `m2Vd…` | `4b8e…` |
  | carol | `s4Lm…` | `c41d…` |

- **click 1**：salt 欄長出來，andy 和 bob 的 hash 值當場變得不一樣（原本相同的兩格，其中一格改變）。
- **click 2**：attacker 再猜一次 `hunter2`——這次他那條線分裂成 N 條，每一列都得帶著那一列的 salt 各算一次。
- **聽眾此刻應看出的事**：**同一個候選密碼在這一列算完的結果，對下一列完全沒用。**
  不管猜中沒有，每一列都得從頭再算一次。
- **講者要說的話**：「salt 不是為了讓 hash 更難反推——它反不反推得回來完全沒變。
  它是為了讓『算一次』不再能算給全部人。」
- **⚠️ 這一頁不要數次數**（「算 3 次」「一千筆就一千次」都不要說）。
  只要把「每一列都要重來」這件事表達出來就夠了；具體的成本是下一頁的事。
- **下一個痛點**：**那他算一次，到底要多久？**

> 空間規則：P4→P5→P6 是**同一張表格在原位演化**，欄位增減用推移動畫，行數與位置固定。
> 聽眾要能一直看著「同一批人的密碼」，不能每頁換一張新表。

### P7　那他算一次，要多久　★

- **畫面上有什麼**：一張**三列**的表。**這張表會活到 P9，所以右邊要預留第二個數字欄的空位。**

  | 單張 RTX 4090 | 裸 SHA-256 |
  |---|---|
  | **算一次**（單價） | **45 皮秒**（一秒 220 億次） |
  | 跑完 6 碼純數字（10⁶ 種） | 45 微秒 |
  | 跑完 8 碼英數（62⁸ ≈ 2.2×10¹⁴ 種） | 約 3 小時 |

- **click 1**：**單價那一列**先出現。這是整頁的地基，也是 P6 那個問句的直接答案。
- **click 2**：6 碼純數字。
- **click 3**：8 碼英數。
- **表格底下一行固定的小字**：「後兩列是**把整個空間跑完**的時間。真實攻擊會先跑字典與規則，通常還更快。」
  這行是用來擋掉「哪有那麼快」的質疑，也是誠實限定——不能省。
- **聽眾此刻應看出的事**：P6 辛苦逼出來的「每一列都要重算」，單價根本不值錢。
- **講者要說的話**：「salt 逼他對每一列重算一次——但他算一次只要 45 皮秒。
  就算 db 有一百萬列，把一個候選密碼對全部列各算一次，也才 45 微秒。」
- **下一個痛點**：**所以要動的不是他重算幾次，是他算一次的單價。**

> 數字來源與換算見〈技術限定與待查證事項〉。
> 這張表的欄位標題必須寫「單張 RTX 4090」——不要寫成「攻擊者」，具體的硬體才有重量。

### P8　那就讓它慢　★

- **畫面上有什麼**：上半是參數演化，下半是最簡模型。
- **click 1**：參數演化，一行一行長出來。

  ```
  hash(password)
  hash(password, salt)
  pbkdf2(password, salt, iterations)
  ```

  講一句：「光看名字大概就猜得到它想幹嘛了。」
- **click 2**：最簡模型長出來。畫成一條鏈，不要畫方塊圖：

  ```
  password ─┐
            ├→ [算一次] → 中間值 ─┐
     salt ──┘                     │
                                  ├→ [算一次] → 中間值 ─┐
            password ─────────────┘                     │
                                                        ├→ …  重複 600,000 次
            password ─────────────────────────────────┘
  ```

- **click 3**：把每一個 `password` 的入口同時高亮。
- **聽眾此刻應看出的事**（這一頁只要他們拿到兩件事）：
  1. **上一輪的結果是下一輪的輸入** → 這條鏈只能一輪一輪走，不能拆開同時算。
  2. **密碼每一輪都要用到** → 攻擊者不能預先算好前面幾輪再省略。
- **講者要說的話**：「所以他只能一條一條算。⋯⋯但別忘了他手上那張卡有一萬多個核心，他可以同時跑一萬條鏈。所以我們真正要看的，還是那張表。」
- **下一個痛點**：那張表現在長什麼樣？

> **教學模型的取捨（必須記錄）**：
> - 「算一次」實際上是 HMAC-SHA256，密碼是它的 **key** 不是被 hash 的資料。畫面上用「password 每輪都接進去」表達，不出現 HMAC 這個詞。
> - 真正的 PBKDF2 是把**每一輪的結果全部混起來**當輸出，不是只取最後一輪。這頁不講；隱藏頁補。
>   → 若有人問「為什麼不能只取最後一輪」，走附錄 C（RFC 的 belt-and-suspenders 原註）。
> - 「一輪餵下一輪」在單一條鏈內是對的；**攻擊者的平行度來自同時跑很多條鏈（很多個候選密碼）**，這句話一定要講，否則 P9 的數字會變得莫名其妙。

### P9　同一張表，第二欄　★

- **畫面上有什麼**：**P7 那張表原地長出第二欄**（位置早就留好了，不推開任何東西）。

  | 單張 RTX 4090 | 裸 SHA-256 | PBKDF2-SHA256 @600k |
  |---|---|---|
  | **算一次** | 45 皮秒 | **68 微秒** |
  | 跑完 6 碼純數字 | 45 微秒 | **約 1 分鐘** |
  | 跑完 8 碼英數 | 約 3 小時 | **約 470 年** |

- **click 1**：第二欄長出來。
- **click 2**：把**「算一次」那一列**整列亮起來 —— 45 皮秒 → 68 微秒。
  倍數就寫在那一列上，聽眾不必心算，也不必相信我。
- **click 3**：把**「跑完 6 碼純數字」那一列**框起來。
- **聽眾此刻應看出的事**——兩個結論，都從同一張表讀出來，講者不下標語：
  - **橫著看**：同一個密碼，成本被乘了約 150 萬倍。這就是 iterations 買到的東西。
  - **直著看**：六碼數字那格，乘完也只有一分鐘。**PBKDF2 不會讓爛密碼變好，它只是把每一格乘上同一個常數。**
- **講者要說的話**：「它是一個乘法，不是一個保護傘。你的密碼本來值多少，它就幫你放大多少倍。」
- **下一個痛點**：這一頁把 `iterations` 講完了。但 P8 的參數清單，其實**還少一格**。

> **這是全場成本敘事的終點。** 之後不再回來調 iterations，也不再比較演算法。
> Argon2 / memory-hard 若要提，只在 P13 收尾一句話，不回到這張表。

### P10　第四個參數　★

- **畫面上有什麼**：P8 的參數演化列，最後一行原地長出第四格。

  ```
  pbkdf2(password, salt, iterations, 輸出長度)
                                     ^^^^^^^^
  ```

- **click 1**：`輸出長度` 長出來，高亮。
- **click 2**：左右對照兩格。
  - 左：`SHA-256(password)` → 固定 32 bytes。旁邊一句：**長度是演算法決定的，你沒得選。**
  - 右：`pbkdf2(…, 32)` / `pbkdf2(…, 16)` / `pbkdf2(…, 64)` → 三種長度都給得出來。
- **click 3**：右邊那格底下浮出一行：`AES-256 需要 32 bytes 的 key`。
- **click 4（立足點）**：把 **RFC 8018 §5.2 的簽章原文**攤開，讓「這個參數到底是幹嘛的」有規格書背書：

  ```text
  PBKDF2 (P, S, c, dkLen)
    Input:   P      password, an octet string
             S      salt, an octet string
             c      iteration count, a positive integer
             dkLen  intended length in octets of the derived key
    Output:  DK     derived key, a dkLen-octet string
  ```

  旁邊三句：**前三個是安全性參數，第四個不是**，它只回答「我要幾個 byte」；
  RFC 原話 *“The length of the derived key is essentially unbounded.”*；
  而輸出的名字，規格書自己就寫 **derived key**。
- **為什麼要引原文**：後面講 .NET 那段 code 時（P12、P13）需要一個不是我說了算的立足點 ——
  「長度是輸入參數」這句話是規格書寫的，不是我為了罵那個 API 才發明的。
- **聽眾此刻應看出的事**：存密碼根本用不到「指定長度」這個能力。它會存在，是因為**產物本來就不是要拿去比對的指紋，是要拿去當鑰匙的材料**。
- **講者要說的話**：「到這裡，封面那五個字才真的能讀了——**Key Derivation**。它從頭到尾都不是在做 password hashing，是在**從密碼生出鑰匙**。password hashing 只是它剛好也能做的事。」
- **下一個痛點**：那同一個密碼，這兩件事能不能一起做？

> **這一頁是全場的轉軸。** P1 掛在封面上沒人讀的那兩個字，在這裡被兌現。
> 原草稿放在隱藏答疑的「key derivation 在這是什麼意思」，就是這一頁——它不是答疑，它是主線。

### P11　它其實什麼都不是，就是一串 bytes　★

- **click 1**：左邊一個呼叫框，四個 input 逐行列著（`password / salt / iterations / 長度`）；
  一條線畫到右邊一個灰白色的 bytes 方塊 `a3f1 9c2e …`，底下寫 `32 bytes`，再底下一句「**就這樣。它沒有身份。**」
  呼叫框下面兩行小字：**「同樣這四個 input → 永遠是同一串」**、**「而且算一次很貴（68 微秒）」**。
- **click 2**：從那串 bytes 散出四條線，接到四個並列的用途 —— 順序與數量都不重要，就是要看起來很隨性：

  | 你可以拿它 | 那它此刻是 |
  |---|---|
  | 送出去，讓 server 比對 | 「指紋」 |
  | 留在本機，拿去解資料 | 「鑰匙」 |
  | 抽 64 bytes，自己切一半 | 前 32 加密、後 32 算 MAC |
  | 或者你只是想要一串難猜的 bytes | 它不在乎你拿它幹嘛 |

- **click 3**：在 bytes 與用途之間落下一條紅色虛線，兩側各一個標籤：
  左「**RFC 8018 管到這裡為止**」、右「**右邊這些，規格書一個字都沒寫**」。
- **聽眾此刻應看出的事**：它就是一個**確定性**、**很貴**、**長度你說了算**的 bytes 產生器。
  沒有「PBKDF2 的幾種用法」這種東西 —— 用途是使用者給的。
- **下一個痛點**：**那我們那段 code，抽了多少、拿去幹嘛？**

> **不要出現任何產品名稱。** 也不要把四個用途講成「最佳實務清單」，它們只是例子。
> （技術補充，只放講稿：真要從一次輸出切出好幾把 key，正統做法是再過一層 HKDF
> 或用不同 salt 各 derive 一次。這不影響「用途由你決定」這個結論，所以不上畫面。）

### P12　那我們那段，抽了多少、拿去幹嘛

- **畫面上有什麼**：P3 那段 code 原封不動搬回來，這次逐行讀。
- **click 1**：高亮兩行 `GetBytes` → 左下浮出「**抽了多少**：32 + 16 = **48 bytes**」。
- **click 2**：高亮 `CreateEncryptor(key, iv)` → 右下浮出「**拿去幹嘛**：自己切開，前 32 當 key、後 16 當 IV，餵給 AES」。
- **聽眾此刻應看出的事**：這就是 P11 那張圖的其中一種用法而已 —— 抽一段 bytes，自己切，自己決定拿去幹嘛。
- **講者要說的話**：「所以這個 class 叫 `Rfc2898DeriveBytes`，不叫 `PasswordHasher`。它就是照字面在做事。」
- **一定要把「48」唸出來**，下一頁整頁都在問這個數字是誰決定的。
- **下一個痛點**：那它為什麼被廢棄？

### P13　那它為什麼被廢棄　★

**這一頁只有一個論證。** 不要拆成兩件事講。

- **畫面配置**：左＝舊 code（+ 之後長出新 code）；右＝ RFC 簽章 + 兩個方塊。
- **右上角常駐**：`PBKDF2 ( P, S, c, `**`dkLen`**` )`，`dkLen` 打亮，旁邊小字 `RFC 8018 §5.2`。
- **click 1**：舊 code 第一行高亮 → 左邊浮出「這個建構子拿到了 **P**、**S**、**c** —— 然後就沒了。**dkLen 呢？**」
  右邊同時長出紅框：

  > **dkLen 被推遲到 GetBytes 了**
  > 而且是一次一次地拿。所以這個物件**不是一次 PBKDF2** —— 它是一條 stream，而 RFC 裡沒有這種東西。
  > **少了一個 input，它就不是規格書定義的那個函式了。**
  > *“… offers a non-standard usage by streaming bytes back … the algorithm should be used as a one-shot.”*
  > `SYSLIB0060 · .NET 10 · 全部建構子`

- **click 2**：左邊長出新寫法（`Rfc2898DeriveBytes.Pbkdf2(…, keyLen + ivLen)`，註解 `← 長度，在這裡`）；
  右邊補一句：「新的靜態方法把 input 補回來了。它沒有變聰明 —— 它只是**不讓你不講長度**。」
- **click 3（收束）**：置中一句 ——
  「而上一頁那個 **48**，從來沒有人決定過它 —— 那是兩次 `GetBytes` 自己掉出來的。
  一個你沒決定過的數字，本來就不該是這個函式的輸入。」
- **聽眾此刻應看出的事**：廢棄的理由不是「這個 API 不好用」，而是**它的形狀對不上規格書**。

## 視覺語意與節奏

- **db 表格是同一張，不換**（P4→P5→P6）。欄位增減用推移，行數與帳號固定，聽眾要一直看得到「同一批人」。
- **成本表在 P7 就要把第二欄的位置留好**（透明佔位），P9 是「填進去」不是「擠出來」。這是全場唯一需要預留空間的地方。
- **參數演化列是同一列**（P8 三行 → P10 長出第四格）。不要在 P10 另外畫一張新的參數表。
- **P3 的 code 與 P12 的 code 必須逐字相同**，連縮排都一樣。P12 是「回到現場」，不是「另一個例子」。
- **鎖頭 = 這串 bytes 拿去加密了**；沒鎖頭 = 它是拿去比對的。只在 P11 用一次，不濫用。
- **延後命名**：
  - `Key Derivation` 這兩個字，封面掛著但 P10 才解釋。
  - P11 全程只寫職責（「證明我是我的那個值」／「開我資料的那把」），不寫任何產品的正式名稱。
  - `SYSLIB0041` / `SYSLIB0060` 兩個代號到 P13 才出現，而且是**附註**，不是標題。
- **全貌**：這場沒有架構圖。獎賞是 P13 那兩個紅框——聽眾發現「廢棄的兩個理由，剛好就是我剛剛自己推出來的兩件事」。

## 技術限定與待查證事項

### 已確認的前提與來源

| 主張 | 來源 |
|---|---|
| `SYSLIB0060` 起於 **.NET 10**，廢棄 `Rfc2898DeriveBytes` **所有**建構子；理由是 one-shot 語意，原話 “…streaming bytes back… should be used as a one-shot” | [MS Learn SYSLIB0060](https://learn.microsoft.com/en-us/dotnet/fundamentals/syslib-diagnostics/syslib0060) |
| `SYSLIB0041` 起於 **.NET 7**，廢棄 5 個套用預設值的建構子；預設為 **1000 輪 + SHA-1**，是 .NET Framework 2.0 時代訂的 | [MS Learn SYSLIB0041](https://learn.microsoft.com/en-us/dotnet/fundamentals/syslib-diagnostics/syslib0041) |
| 靜態 `Rfc2898DeriveBytes.Pbkdf2(...)` 是官方指定的替代寫法 | 同上 |
| OWASP 建議 PBKDF2-HMAC-SHA256 **600,000** 輪，校準目標約 **0.1 秒**；且 Argon2id 才是首推，PBKDF2 主要留給 FIPS 場景 | [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) |
| hashcat v6.2.6 / RTX 4090：SHA2-256 = 21,975.5 MH/s；PBKDF2-HMAC-SHA256 @999 輪 = 8,865.7 kH/s | [benchmark gist](https://gist.github.com/Chick3nman/32e662a5bb63bc4f51b847bb422222fd) |

### P7 / P9 表格的換算過程

```
裸 SHA-256      = 2.1976e10 H/s   → 單價 1/2.1976e10 = 4.55e-11 s ≈ 45 皮秒
PBKDF2 @600k    = 8.8657e6 × (999 / 600000) = 1.476e4 H/s
                                  → 單價 1/1.476e4 = 6.78e-5 s ≈ 68 微秒

10^6  / 2.1976e10 = 4.55e-5 s   → 45 微秒
10^6  / 1.476e4   = 67.7 s      → 約 1 分鐘
62^8 = 2.1834e14
2.1834e14 / 2.1976e10 = 9,935 s → 約 2.8 小時
2.1834e14 / 1.476e4 = 1.479e10 s → 約 469 年

倍數 = 2.1976e10 / 1.476e4 ≈ 1.49e6 → 約 150 萬倍
（與理論值 2 × iterations = 1.2e6 同量級，可互相驗算）
```

**「8 碼英數只要 3 小時」是對的，而且要主動講清楚它的限定：**

- 算術：`62^8 = 2.1834e14` ÷ `2.1976e10 H/s` = 9,935 秒 ≈ 2.8 小時。就是這樣。
- 這是**窮舉整個空間**的時間，不是平均破解時間（平均只要一半）。
- 而且 `62^8` 假設的是**完全隨機的 8 碼**。真人密碼熵低得多，
  字典 + 規則跑一跑通常幾分鐘內就掉一大半 —— 真實情況比表上更糟，不是更好。
- 對照組：同一張卡 MD5 約 164 GH/s、NTLM 約 288 GH/s，比 SHA-256 再快一個數量級。

### 講者心裡有底就好，不進簡報

`600,000` 輪在一般 CPU 上是**幾十毫秒**的量級（本機 i5-13600KF 單執行緒實測約 54 ms），
正好落在 OWASP 校準的「約 0.1 秒」上。被問到「為什麼不乾脆設一億輪」時口頭回答即可 ——
**不要把自己機器的數字放上投影片**，主線的成本敘事在 P9 已經收乾，多一組硬體只會分散焦點。

### dkLen 到底是什麼參數（P10 的立足點）

RFC 8018 §5.2 把四個參數分得很清楚：

| 參數 | 規格書怎麼寫 | 性質 |
|---|---|---|
| `P` | password, an octet string | 安全性 |
| `S` | salt, an octet string | 安全性（防攤提） |
| `c` | iteration count, a positive integer | 安全性（成本乘數） |
| `dkLen` | **intended length in octets of the derived key** | **介面** —— 我要幾個 byte |

並且明講：*“The length of the derived key is essentially unbounded.”*
所以「前三個保證安全性、第四個是使用面的彈性設定」這個理解**是對的**。

**但 dkLen 不是完全免費**，這一點要記住，因為 P13 會用到：

```
l = CEIL (dkLen / hLen)          每一個 block 都要跑完整的 c 輪
```

跟 PRF 要超過 `hLen` 的量，成本就線性倍增；而攻擊者否決一個錯的候選密碼，
往往算完第一個 block 就夠了 —— **這個代價不對稱地落在防守方身上**。
套回那段 code（假設 AES-256）：SHA-1 的 `hLen = 20`，抽 48 bytes → `l = 3` → 實際跑 3000 輪。
（`alg` 是不是 AES-256 待作者確認；若是 AES-128 則 `l = 2`、2000 輪。）

### 為教學而合併／省略的細節

- **P8 的最簡模型省略了 XOR**。真正的 PBKDF2 是 `T = U₁ ⊕ U₂ ⊕ … ⊕ U_c`，不是只取最後一輪。省略不影響「成本 = 輪數 × 單價」這個唯一要傳達的結論，但**不可以說成「只取最後一輪」**——那是錯的。隱藏頁補精確定義。
- **P8 沒有出現 HMAC**。密碼是 HMAC 的 key 這件事，用「password 每輪都接進去」的畫面表達。
- **P8 的「只能一條一條算」必須立刻補上「但他可以同時跑一萬條」**，否則 P9 的數字說不通。這句話不是免責聲明，它是 P9 那張表成立的前提。
- **P11 不出現任何產品名稱**。分岔的實例是抽象的「送出去的／留下來的」。

### 尚待作者確認或查證的主張

1. **你們在 .NET 8 時代，是不是其實已經有 `SYSLIB0041` 警告了？**
   `new Rfc2898DeriveBytes(password, salt, iterations)` 這個簽章在 .NET 7 就已經在廢棄清單裡。
   若當時就有警告（只是沒人處理），P13 click 1 的講法要改成「這個警告其實掛在那裡兩年了」——
   那反而更好，因為它親自示範了「1000 輪 + SHA-1 這種預設值有多容易被忽略」。
   **請確認 build log。**
2. **`salt` 是每次隨機產生，還是寫死／從設定檔來的？**
   這決定 P13 click 4 的 IV 問題有多嚴重——如果 salt 也是固定的，那同一份明文每次加密會得到完全一樣的密文。
   若確實如此，這句話要不要說重一點，由你決定（但仍**不建議展開**，會偏離主線）。
3. **`iterations` 目前實際的值是多少？** 若遠低於 600,000，P13 click 1 可以直接把你們的實際值放進 P9 那張表換算，
   衝擊力比講「預設 1000」更大。但這也可能不適合對外講——由你判斷。

### 不能被濃縮成 bullet 的段落

- **P5 / P6**：「一次動作 vs 一千次動作」只有動畫成立。寫成文字就變回「salt 讓 hash 不一樣」這種聽過就忘的句子。
- **P9**：那兩個結論必須是聽眾**從表上讀出來**的。任何一句總結性的標語都會把它變成「被告知」。
- **P10**：左右對照（固定長度 vs 可指定長度）是這一頁的全部。不能寫成「PBKDF2 支援自訂輸出長度」。
- **P11**：「用途隨你」這件事只有靠**四個並列的例子 + 那條紅線**才成立。
  寫成「PBKDF2 的兩種常見用途」就整個反過來了 —— 那正是這一頁要打掉的誤解。
- **P13**：「RFC 有四個 input，這個建構子只收三個」是一條完整的論證。
  不能列成「obsolete 的原因清單」，也不要在這裡補 SHA-1 那條。

### 建議的隱藏頁（放在最後，備詢用）

- **A**　PBKDF2 精確定義（RFC 8018 §5.2）：`U₁ = PRF(P, S‖INT(i))`、`U_j = PRF(P, U_{j-1})`、
  `T_i = U₁ ⊕ … ⊕ U_c`、`DK = T₁‖…‖T_l` 截斷至 dkLen；外加「password 是 HMAC 的 key」與「dkLen 不是免費的」兩格。
- **B**　dkLen 抽太多，多付的是你：`l = ⌈48/20⌉ = 3` → 那段 code 實際跑 3000 輪，而多出來的兩個 block 買不到任何安全性。
- **C**　為什麼要 XOR 全部而不是只取最後一輪 —— 附 RFC 的 belt-and-suspenders 原註
  （遞迴是為了拿掉攻擊者的平行度，XOR 是為了防遞迴退化，兩件事分開）。
- **D**　`SYSLIB0041` 的五個建構子清單 + `SYSLIB0060` 的官方 workaround 原文與範例。
- **E**　PBKDF2 vs bcrypt / scrypt / Argon2：memory-hard 是在擋什麼。
- **F**　IV 為什麼不該從密碼導出，正確做法（`RandomNumberGenerator.GetBytes` + 隨密文存）。
- **G**　P11 那個分岔在真實產品裡長什麼樣（bitwarden：Master Key 以 email 為 salt、
  Master Password Hash 以 master password 為 salt）。
  ⚠️ 若要用，client 端第二次的實際輪數與官方「總共 700,000 輪」的拆帳，兩份來源說法不一致，
  **上台前需再查 whitepaper 與 clients 原始碼**。
