# Zero knowledge and bitwarden

1. agenda

分四段：
一、用登入感受零知識 —— 保護「密碼」
二、零知識怎麼保護「資料」
三、Bitwarden 還多做了什麼？
四、完整走一遍 register / login / unlock / lock / logout

一和二是完全連貫的一條線 (只是保護的東西從密碼換成資料)
三才開始講 Bitwarden 這個具體產品
四是驗收 不教新東西 只是把前面的圖換成一個時間軸走完

=====================================================================
第一段　用登入感受零知識 (保護密碼)
=====================================================================

2. 用圖 + 動畫的方式展現出純明文註冊 + 登入
會發現為了登入 讓 server 存了太多資訊 (knowledge) 徒增風險，如 db 被偷

3. 用圖 + 動畫的方式展現出 server hash 註冊 + 登入比對 hash
會發現 server 雖然沒有存有效 knowledge 但在明文剛進來的時候仍有風險

4. 用圖 + 動畫的方式展現出 client hash 註冊 + 登入比對 hash
其實是 2. 的變型版
好處是 server 已經不知道原始密碼了
但 2. 的壞處一樣還在: 如果 db 被偷了，還是有辦法登入此系統，只是因為沒有明文，不會擴散到其他系統
而竟然 2. 的這點可以用 3. 解決
那理所當然可以推出 4. + 3.

5. 用圖 + 動畫展現出 client hash + server hash 等等

---
以上都要展現出 「秘密在哪，看得出為什麼安全被偷也沒事，人失誤多 log 了也沒事」

現在密碼保護住了
但是進一步要怎麼保護 「資料」？
因為密碼是利用不可逆只驗證來保護
但資料必須要可逆！

=====================================================================
第二段　零知識保護資料
　　　　※ 這一段完全不提 Bitwarden，也還沒有 symmetric key
　　　　※ 只寫職稱不寫名字，名字留到第三段才對號入座
=====================================================================

6. 用圖 + 動畫展現出 server 上長出一個 vault

這才是我們真正要存的東西
前面五步都只是為了進得來 現在才要談進來之後放什麼

這一定要是密文 這件事很直覺
如果是明文 那前面密碼保護得再好都白說了
等於門鎖得很緊 但東西堆在門外

會發現這裡跟第一段有一個根本差異
hash 是因為「回不去」才安全
但資料必須回得去 不然存了等於沒存
第一段的所有招式 在這裡全部用不了

=> 所以下一題：這個密文是怎麼來的？

7. 資料要可逆 就代表一定要有一把「開得回來」的鑰匙
那這把鑰匙從哪來？直覺是拿第一段已經有的東西來用

用圖 + 動畫展現出 直接拿 client 送出去的那個 hash 當加密鑰匙
會發現 server 手上有一模一樣的東西 所以 server 解得開
第一段辛苦保護的密碼 在這裡整個白做

=> 只要拿 server 也有的東西來加密 就一定行不通
   所以鑰匙只能從 server 沒有的地方生出來

8. 那就退回 client 盤點一次 現在誰手上有什麼

承接第 5 步那張圖 先讓觀眾看清楚現況
　client 格子：hunter2 (明文密碼) → 本機 hash
　server 格子：那個 hash + 明文的 vault

動畫一：從 hunter2 再拉出第二條線 指到一把 key
　　　　同一個密碼 除了算 hash 還能再算出一把鑰匙
　　　　它跟 hash 互相推不回去 而且它從頭到尾不送出去
　　　　(這是整場唯一一次「憑空多一條線」 所以要慢 要停)

動畫二：把 server 格子裡的明文 vault 整包搬到 client
　　　　加密只能發生在有鑰匙的那一邊 資料得先回到自己手上

動畫三：key + vault 結合 產生加密後的 vault 再送回 server 格子

結束時兩邊各剩下什麼 畫面上要看得很清楚
　client：hunter2、hash、key、明文 vault
　server：hash、加密的 vault

問一次：現在 server 知道什麼？
- 一個驗證得了 但推不回密碼的值
- 一包加密的 vault
- 解得開它的那把鑰匙 —— 它根本沒有

---
第二段結束

同一個密碼 現在長出兩樣東西
一個是「給 server 看的」 一把是「永遠不出門的」

到這裡 零知識保護資料的最小版本已經成立了
server 存著一包它永遠打不開的東西

=====================================================================
第三段　Bitwarden 還多做了什麼？
=====================================================================

承上：第二段那套已經完全能用了 —— server 存著一包它永遠打不開的東西
第三段不是「補一個沒解決的洞」
是「這東西一天要用幾十次 Bitwarden 怎麼讓它變得能用」

9. 先講痛 一個名詞都不出現

加密的 vault 拿回本機 一定要解開才用得了
而那把 key 是密碼算出來的 => 想開 vault 就得有密碼 這兩件事現在綁死在一起

方案 A：每次要用都重打一次密碼
　　　　安全上完全沒問題
　　　　但一天幾十次 沒有人受得了

方案 B：第一次打完密碼解開後 把明文 vault 存在本機
　　　　方便 但明文從此永遠躺在這台裝置上
　　　　前兩段的努力 在自己的硬碟上破功

=> 有沒有折衷？不用一直打密碼 也不要在本機留明文
   (這一頁只有「密碼」「vault」「key」三個字 沒有任何專有名詞)

10. 要回答這題 得先把圖看清楚 —— 這時候才貼名字

把第二段最後那張圖原封不動搬回來 幫每個格子標上 Bitwarden 的名字
　hunter2　　　　　　= master password
　那把 key　　　　　 = Master Key
　送出去那個 hash　　= Master Password Hash
　加密的 vault　　　 = 加密的 vault

圖一點都沒變 只是貼標籤 觀眾不需要重新理解任何東西

(取捨：Bitwarden 實際上在 Master Key 之後還有一步 Stretched Master Key
 那一步是為了湊出足夠的金鑰材料 對「東西在誰手上」完全沒有影響
 今天把它併進 Master Key 一起講 不另外開一個名詞)

貼完名字之後 讓大家盯著這張圖 把剛才那個兩難的責任歸屬找出來
　master password → Master Key → 直接對 vault 做事
問題就出在最後那一段：Master Key 直接鎖著 vault
所以「想開 vault」必然等於「手上要有 master password」
剛才那個兩難 完全是這一條線造成的 —— 不是密碼學的問題 是接線的問題

11. 就在同一張圖上 在 Master Key 和 vault 中間插一把新的鑰匙

用圖 + 動畫展現出 兩者中間長出一把隨機產生的 Symmetric Key
　vault ← 被 Symmetric Key 鎖
　Symmetric Key ← 被 Master Key 鎖 (鎖起來的那份存在 server = Protected Symmetric Key)

Master Key 從此不再碰 vault 它只負責開那一小把
=> 「開 vault 要什麼」跟「那個東西怎麼保管」被拆開了
　 Symmetric Key 可以被 Master Key 鎖 也可以被別的東西鎖
　 剛才那個兩難的出口 就在這個「也可以」

回頭問一次：現在 server 手上有什麼？

(順帶：改密碼時只要重包那一小把 vault 一個字都不用動
 換鎖頭 不用換保險箱裡的東西 —— 講一句就過 不要展開成新課題)

12. 鏡頭拉到非常局部：全場最複雜 但也最精妙的一張

其他東西全部推開 畫面上只留這幾樣
　Master Key
　加密的 Symmetric Key
　加密的 vault
　session key (這一張的過程中才會冒出來)

要講清楚的是 unlock 那一瞬間到底發生了什麼
　Master Key 解開 Symmetric Key
　隨機產生一把 session key
　用 session key 把 Symmetric Key 重新鎖一次 放在本機
　從此只要有 session key 就開得了 vault 不必再有 master password

這張要明講「這是今天最繞的一張」
給觀眾心理準備 也給自己一個放慢速度的理由

=====================================================================
第四段　完整走一遍
=====================================================================

13. 把前面所有的圖全部推掉 換成一個記分板

三欄 從頭記到尾
　server 有什麼
　本機硬碟有什麼
　本機 memory 有什麼

依序走完
　register
　login
　unlock
　lock
　logout

每一步只改動記分板上的幾格
觀眾要看的是「什麼被加進來 什麼被抹掉」 不是再學一次機制

lock 和 logout 的差別在這個板子上一眼可見 不用再解釋
　lock　 ：memory 清空 硬碟留著鎖住的東西 => unlock 不需要連網
　logout：memory 清空 硬碟也清空 => 必須連網跟 server 重拿

走完 register 那一步 完整的架構圖其實就自己長出來了
所以不再另外放一張「完整架構圖」 這個記分板就是獎賞

最後一次問：現在 server 手上有什麼？
=> 一包它永遠打不開的東西
　 它不是承諾不看 是沒有能力看

附錄. CLI 上的 BW_SESSION

第 12 張那把 session key 在 CLI 上是看得見摸得到的
CLI 每跑一次指令都是新的 process => 記分板上「memory」那一欄在 CLI 根本不存在
所以只能把鎖起來的 Symmetric Key 放在硬碟 鑰匙交給使用者自己拿著 就是 BW_SESSION
再 unlock 一次會換一把新的 舊的不是被作廢 是它能開的東西被覆寫掉了
(login 拿的是跟 server 講話的憑證 unlock 拿的是解本機資料的鑰匙)

全域視覺規則

A. 只要是「被加密過的東西」 一律在物件上掛一個小的上鎖 badge
   加密的 vault、Protected Symmetric Key、被 session key 鎖起來的那份 …… 都要有
   沒有鎖的就是明文 觀眾掃一眼畫面就知道哪些是打得開的
   badge 是狀態不是裝飾 —— 同一個物件被鎖起來的前後 用同一個框加上/拿掉 badge
   不要換成另一個長得不一樣的框

B. 過程中才長出來的物件 絕對不能把既有的東西擠大或擠開
   觀眾的眼睛正盯著原本那些格子 位置一動 前面建立的空間感就毀了
   兩種做法擇一：
   1. 一開始就把空間保留好 只是不顯示 (透明度 / 空的佔位)
      → 預設用這個
   2. 真的要刻意藏起來、不先給空間的話
      那「把空間推開」本身也要是一段動畫 不能瞬間跳位
      → 只在「這個東西的出現本身就是重點」時才用 例如第 6 步的 vault

C. 每一次動畫只發生一件事
   一個 click 只做一件：長出一條線 / 搬一個物件 / 加一個鎖
   要講的話講得完那一件事 才進下一個 click

---
製作原則

1. 完整的全貌是獎賞 不是教材 只能出現在最後 不能出現在開頭
   而且最後那個全貌不是靜態架構圖 是第四段那個一路走完的記分板
2. 畫面上寫職稱 不寫名字
   「證明我是我的那把」/「開我資料的那把」/「真正鎖著 vault 的那把」/「被鎖起來的那把鑰匙」
   第一二段完全不出現官方名稱 第三段才對號入座
   觀眾追的是職務 不是名詞 而職務是他自己推出來的 所以不用背
3. 「現在 server 手上有什麼？」是第一段用了四次的同一把尺
   第二三段每次畫面變動完 都回到同一個問句問一次
   第四段整個記分板就是這把尺的完全體 (再多兩欄)
   這樣四段不是四場演講 是同一條線
4. 每一步都要能回答「上一步哪裡痛」 不能是「接下來介紹某某機制」
   痛要先講具體情境 (每天打幾十次密碼) 再講機制
5. 一二段是同一條推導 (保護密碼 → 保護資料) 中間不切斷
   三段是「已經成立的東西 拿去天天用會怎樣」
   四段不教任何新東西 只驗收
6. 不下抽象結論 (例如「一把鑰匙不能同時做兩件事」這種標語)
   每一步的結論都要能直接指著畫面上的格子講
   「server 那格裡有一模一樣的東西 所以他解得開」比任何原則都有用
