但 2. 的壞處一樣還在: 如果 db 被偷了，還是有辦法登入此系統，只是因為沒有明文，不會擴散到其他系統

那理所當然可以推出 4. + 3.

以上都要展現出 「秘密在哪，看得出為什麼安全被偷也沒事，人失誤多 log 了也沒事」

現在密碼保護住了
但是進一步要怎麼保護 「資料」？

6. 用圖 + 動畫展現出 server 上長出一個 vault

這才是我們真正要存的東西
前面五步都只是為了進得來 現在才要談進來之後放什麼

這一定要是密文 這件事很直覺
如果是明文 那前面密碼保護得再好都白說了
等於門鎖得很緊 但東西堆在門外

會發現這裡跟前半場有一個根本差異
hash 是因為「回不去」才安全
但資料必須回得去 不然存了等於沒存

=> 所以下一題：這個密文是怎麼來的？

7. 資料要可逆 就代表一定要有一把「開得回來」的鑰匙
那這把鑰匙從哪來？直覺是拿前半場已經有的東西來用

用圖 + 動畫展現出 直接拿 client 送出去的那個 hash 當加密鑰匙
會發現 server 手上有一模一樣的東西 所以 server 解得開
前半場辛苦保護的密碼 在這裡整個白做

=> 問題不是鑰匙不夠強 是這把鑰匙被要求做兩件事

---
一把鑰匙不能同時做兩件事
以下每一次分裂 都是因為有人叫一把鑰匙做兩件事 然後壞掉了
動畫上就是「一把鑰匙裂成兩把」 畫面永遠只發生一件事
---

8. 第一次分裂：證明我是我 / 開我的資料

用圖 + 動畫展現出 從 master password 長出一個根 再裂成兩條
一條送去 server 只負責認證
一條留在本機 只負責解密
兩條互相推不回去 (就是前半場那個「回不去」 再用一次)

會發現 server 能驗證你是你 但沒有能力解開你的資料
不是它保證不看 是它手上根本沒有那把

(職稱：根 = Master Key，送出去那條 = Master Password Hash，留下那條 = Stretched Master Key)

回頭問一次：現在 server 手上有什麼？

9. 那就用留下來那把直接鎖 vault 吧

用圖 + 動畫展現出 Stretched Master Key 直接加密整個 vault
可以動 沒問題
但問一句：改 master password 會發生什麼事？

會發現 鑰匙一換 整個 vault 要全部重新加密一遍
資料越多越痛 而且重加密的當下所有明文都得攤開

=> 第二次分裂：鎖資料的鑰匙 / 綁定密碼的鑰匙

用圖 + 動畫展現出 中間插一把隨機產生的鑰匙
vault 被這把隨機鑰匙鎖
這把隨機鑰匙再被密碼衍生物鎖起來

會發現 改密碼只要重包那一小把 vault 一個字都不用動
換鎖頭 不用換保險箱裡的東西

(職稱：隨機那把 = Symmetric Key，被鎖起來的那把 = Protected Symmetric Key)

回頭問一次：現在 server 手上有什麼？

10. 那每次要用都要重打一次 master password 嗎？

太煩 但解開的鑰匙一直留著 又等於根本沒鎖

=> 第三次分裂：長期的 / 臨時的

用圖 + 動畫展現出兩種「關掉」的差別
lock：把鑰匙丟掉 鎖著的東西留在本機
logout：連鎖著的東西一起丟掉

會發現 unlock 只是把鑰匙重算一次 完全不需要問 server
所以 unlock 可以離線 login 不行
因為解密從來就不是 server 的工作

(CLI 上這把臨時鑰匙就是 session key
 它叫 session 但不是通行證 是鑰匙
 再 unlock 一次會換一把新的 舊的不是被作廢 是它能開的東西被覆寫掉了)

11. 現在才把完整的圖攤開

用圖展現出從 email + master password 一路到 vault 的全貌
到這裡九個角色觀眾一個都不用背
因為每一個出現的時候 都是他自己剛剛意識到「這裡少了點什麼」

最後一次問：現在 server 手上有什麼？
=> 一包它永遠打不開的東西

---
製作原則

1. 完整架構圖是獎賞 不是教材 只能出現在最後 不能出現在開頭
2. 畫面上寫職稱 不寫名字 官方名稱用小字放在下面
   「證明我是我的那把」/「開我資料的那把」/「真正鎖著 vault 的那把」/「被鎖起來的那把鑰匙」
   觀眾追的是職務 不是名詞 而職務是他自己推出來的 所以不用背
3. 「現在 server 手上有什麼？」是前半場用了四次的同一把尺
   後半場每次分裂完都回到同一個畫面問一次
   這樣兩個半場不是兩場演講 是同一條線
4. 每一步都要能回答「上一步哪裡痛」 不能是「接下來介紹某某機制」
